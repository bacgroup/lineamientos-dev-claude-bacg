# Changelog 2026-11

### 2026-11-16 · PLG-DFF2 · Plugin — compuertas de cumplimiento (no de carga), OK flexibles y autonomía total, Superpowers como eje, revisión de calidad multi-pasada, journey UX y mockups obligatorios en UI (retrabajo R-MOD-V2)
- Qué cambió: El plugin pasa a controlar cumplimiento y no sólo carga: un OK del usuario cubre todo hasta DEV, Superpowers vuelve a ser el motor obligatorio, la revisión es de calidad en tres pasadas, y la UI exige journey, mockups, referencia y paridad. Portado a dev-fullflow 4.4.0.
- Dónde: .bacg-dev/proyecto.yml, .claude-plugin/marketplace.json, package.json, plugin/.claude-plugin, plugin/hooks, plugin/scripts
- Alcance: Plugin de origen y dev-fullflow

### 2026-11-16 · PLG-CLOUD · Plugin — la experiencia en Claude Code en la nube (handoff PowerFy 16/11): GitHub por REST sin gh auth, odoo-skills por git anónimo, compuertas que ven escrituras por Bash y --sin-previa con frase, fetch real en el alta, plugins sincronizados, rojos de Odoo, specs en qa/, bundles compartidos y documentación.
- Qué cambió: El plugin funciona en Claude Code en la nube sin falsos 'todo OK': GitHub por REST, alta y previa que dicen lo que no verificaron, odoo-skills por git anónimo, y compuertas que no se esquivan por Bash ni por la API. Portado a dev-fullflow 4.5.0.
- Dónde: .bacg-dev/proyecto.yml, .claude-plugin/marketplace.json, plugin/.claude-plugin, plugin/scripts
- Alcance: Plugin de origen y dev-fullflow

### 2026-11-16 · PLG-BACKLOG · Plugin — fuente única del backlog (hallazgo 8 de PLG-CLOUD): una sola fuente por proyecto, aviso si hay dos que difieren y migración de la copia central al repo.
- Qué cambió: El backlog tiene una sola fuente declarada (backlog: repo) y, mientras haya dos copias, abrir y cerrar las fusionan sin perder filas, columnas ni texto. backlog migrar deja el repo como fuente. Portado a dev-fullflow 4.6.0.
- Dónde: .claude-plugin/marketplace.json, plugin/.claude-plugin, plugin/scripts
- Alcance: Plugin de origen y dev-fullflow

### 2026-11-16 · PLG-BKL2 · Plugin — el backlog con filas separadas por líneas en blanco bajo un solo encabezado: abrir y cerrar duplican la fila (regresión de la 4.6.0)
- Qué cambió: El backlog con grupos de filas separados por líneas en blanco vuelve a ser una sola tabla: abrir y cerrar actualizan la fila existente en lugar de duplicarla (regresión de la 4.6.0). Portado a dev-fullflow 4.6.1.

- Alcance: Plugin de origen y dev-fullflow

### 2026-11-19 · PLG-MOCK · El mockup se pregunta cuando el cambio de UI es técnico o chico
- Qué cambió: Si un cambio de pantalla es técnico o chico, el agente te pregunta si hace falta mockup; si decís que no, queda registrado con tu frase y se sigue pidiendo el recorrido del usuario.
- Dónde: plugin/scripts
- Alcance: Plugin

### 2026-11-19 · PLG-SEG · Checklist de seguridad de aplicaciones (OWASP) con referencia ISO 27001 y SOC 2
- Qué cambió: La revisión de cada RQ aplica una lista de 13 controles de seguridad (OWASP, con ISO 27001 y SOC 2 como referencia); un problema de acceso, entradas, sesiones, secretos o datos personales es crítico.
- Dónde: sin archivos de producto
- Alcance: Plugin

### 2026-11-19 · PLG-DEPS · Los plugins requeridos se instalan solos y sin ellos no se trabaja
- Qué cambió: El alta exige los plugins que el ciclo necesita y da los comandos exactos para instalarlos; si falta uno, no se edita código, y el plugin nunca se apaga por eso.
- Dónde: plugin/scripts
- Alcance: Plugin

### 2026-11-19 · PLG-PRREV · Revisor automático independiente en PR y push
- Qué cambió: rq.mjs revisor-pr instala en cada repo un revisor automático en GitHub que revisa PR y push de agentes externos con las reglas del proyecto y la lista de seguridad; comenta y sólo frena ante un crítico. Falta la prueba en vivo (secret y protección de rama).
- Dónde: plugin/plantillas, plugin/scripts
- Alcance: Plugin

### 2026-11-19 · PLG-SP · Superpowers como columna vertebral (segunda pasada)
- Qué cambió: Superpowers pasa a ser la base del ciclo: el agente usa toda skill de Superpowers que aplique y, si una prueba de punta a punta falla, depura con método antes de aprobar la revisión. Versión 4.7.0.
- Dónde: .claude-plugin/marketplace.json, plugin/.claude-plugin, plugin/scripts
- Alcance: Plugin

### 2026-11-24 · PLG-TEST-INFRA · Commits sin rechazos falsos: reintento ante falla de infraestructura o timeout de tests, clase del rechazo en el log, aviso si tests.unit no usa {archivos} (PLG-TEST-REL) y pregunta de canon de UI al cierre
- Qué cambió: Los commits ya no se rechazan por tests lentos o cortes de la herramienta de tests: se reintentan una vez y queda anotado. El cierre de un RQ con pantallas pregunta si hay un lineamiento nuevo para el canon de UI.
- Dónde: plugin/scripts, package.json, .claude-plugin/marketplace.json, plugin/.claude-plugin
- Alcance: lineamientos-dev-claude-bacg

### 2026-11-24 · PLG-E2E-ALC · E2E con alcance: aviso si tests.e2e no usa {specs}, verificar dice si corrió la suite completa y cuánto tardó, --completo una sola vez antes de PROD (e2e_completos) y tests.e2e_mapa opcional
- Qué cambió: El E2E corre sólo lo del RQ y la suite completa una vez antes de PROD; el plugin avisa si el proyecto no está configurado así y dice cuánto tardó cada corrida.

- Qué cambió: Siete fricciones del ciclo resueltas: frases en lista, push anotado sólo en el RQ que viaja, stage restaurado si el commit se frena, commit de sólo tests que los corre, no-aplica de sync verificado y prioridad e impacto al abrir.
