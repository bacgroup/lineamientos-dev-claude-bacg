# Backlog

Sólo lo activo, una fila por RQ. El detalle vive en `docs/rq/<código>/`. El cierre mensual va a `backlog-archivo-AAAA-MM.md`. Es la fuente única del tablero "Backlog PowerFy": el tablero se sincroniza desde este archivo (rama `main`) y no tiene datos propios.

Columnas:

- **Estado**, uno solo de esta lista: `Pendiente` · `Decisión pendiente` · `En desarrollo` · `DEV OK - Pendiente QA` · `QA OK - Pendiente PROD` · `En PROD` · `Bloqueado / Parked` · `Descartado`.
- **Inicio** y **Fin** en `dd/mm/aaaa`. Inicio: cuando arranca el desarrollo. Fin: cuando llega a PROD (o se descarta). Vacío si no aplica todavía.
- **Prioridad**: `Alta` · `Media` · `Baja` · `A definir`.
- **Responsable**: quién mueve el ítem.
- **Impacto**: se mantiene porque lo exigen el plugin y su test; el tablero no lo muestra.

Altas y cambios pedidos por un miembro de BACG vía Claude: Claude agrega o edita la fila acá con esos valores (código `PF-<TEMA>` nuevo y único; lo que no se sepa, vacío o `A definir`), hace commit directo a `main` con el mensaje `backlog(powerfy): <código> <qué cambió>` y no toca otras filas. Lo escribe también `rq.mjs` (abrir y cerrar); mientras el plugin no adopte esta lista (PLG-BKL-ESTADOS), corregir a mano el estado que deje fuera de ella.
